## 3. ★ 포렌식 기법 (로그가 없는 구간을 복원하는 법)

이 인시던트의 재사용 가치는 대부분 여기 있다. 수집~authoring 구간은 **정상일 때 로그를 안 남긴다**
(08-08 성공 런도 20:02:01→20:18:29 사이 16분이 무음). 그래서 "침묵"만으로는 아무것도 판정할 수 없다.

**ⓐ DDB `ttl` 역산 = 쓰기 시각.** `ttl = 쓰기시각 + TTL기간` 이므로 `ttl − TTL기간` 으로 초 단위 복원이 된다.
card-cache(TTL 30일)로 "그날 카드 몇 장을 언제 썼나", source-store 로 "어느 소스가 언제 동결됐나"를
재구성해 죽은 지점을 20:01:08~20:01:26 사이로 좁혔다.
⚠️ **source-store 는 이제 못 쓴다** — TTL 폐지(`305ed18`)가 이번 배포에 같이 실렸다(정본 영구보존과 맞바꿈).
card-cache 는 유효.

**ⓑ 꼬리 404 = 소스 통과 마커.** html 소스의 리스팅 링크 끝에는 정크(`/privacy`·`/home` 등)가 붙는데,
루프가 39개를 **끝까지 소진했을 때만** 그 404 가 찍힌다. 정상 경로엔 로그가 없으니 역설적으로
**에러 로그가 유일한 진척 신호**다. 08-08 엔 있고 08-09 엔 없다 = 08-09 는 중간에서 멈췄다.

**ⓒ 반례 — 메트릭 flush 는 생존 신호가 아니다.** "OTEL 익스포터는 독립 스레드이니 flush 부재 = 컨테이너 사망"
이라고 추론했다가 **철회했다**: 41분짜리 성공 런에서도 flush 는 20:01:52 단 1회뿐이었다(측정값이 있을 때만 export).
다음에 같은 오추론을 하지 않도록 반례를 남긴다. 결과적으로 **사망인지 정지인지는 끝내 가리지 못했고**,
가용 텔레메트리로는 가릴 수 없다(컨테이너 레벨 지표 없음).

## 4. 근본 원인

```
_http_get → trafilatura.fetch_url → pycurl 없음(HAS_PYCURL=False) → urllib3 경로
                                        │
        create_pool(timeout=30) ──▶ Timeout(connect=30, read=30)
                                        │
        read 타임아웃은 "총 시간"이 아니라 "읽기 1회" 기준 → 매번 초기화
        서버가 29초마다 1바이트씩 흘리면:  │read│ │read│ │read│ …  ∞
```

- trafilatura 2.1.0 의 두 백엔드 중 **pycurl 경로만** `CURLOPT_TIMEOUT`(총 시간)을 건다. 컨테이너엔 pycurl 이 없다.
- 여기에 `_get_retry_strategy` 가 `backoff_factor = DOWNLOAD_TIMEOUT/2 = 15초`로 재시도(429/5xx)를 겹친다.
  "30초 타임아웃"이라는 직관과 달리 한 URL 이 수 분을 쓸 수 있다.
- **파이프라인은 소스를 한 스레드에서 직렬 처리**하므로, 한 URL 이 막히면 브리핑 전체가 무출력으로 멈춘다.
- 노출 면적이 큰 이유: `max_items=5` 가 HTTP 성공이 아니라 **"신선한 기사 5건"** 을 세기 때문에(window 48h),
  google-dev 는 매일 링크 39개를 전부 시도한다.

**재현으로 확인한 것:** 사고 당일 이후 로컬에서 google-dev 를 돌리면 **4.4초에 정상 완료**
(39링크, 관측된 404 순서와 정확히 일치: `0 /css2` 404 → `1 /glue-icon` 추출실패 → `2 /community` 404 → `3~` 실기사).
즉 **그 소스의 구조적 결함이 아니라 일시적 정지**였다. 그래서 고칠 대상은 "그 소스"가 아니라 **시간 상한의 부재**다.

**왜 두 층인가.** 요청 상한만으론 `39링크 × 20초 = 13분`까지 늘어난다. 예산만으론 한 요청이 예산을 통째로 먹는다.

**왜 `break` 이고 `raise` 가 아닌가.** 한 소스 때문에 브리핑을 죽이지 않는다 —
2026-07-02 인시던트에서 배운 **카드별 격리와 동형**, 이번엔 소스 단위.

**왜 스레드인가.** `signal.alarm` 은 메인 스레드 전용인데 AgentCore 는 async task 스레드에서 파이프라인을 돌린다.
데몬 스레드라 프로세스 종료를 막지 않는다.

**값의 근거(실측).**

| 구간 | 실측 정상 | 채택값 | 여유 |
|---|---|---|---|
| 요청 1건 | 0.2~1.2초(로컬), prod ~0.6초/링크 | **20초** | ~17배 |

  타임아웃 의미가 라이브러리가 아니라 우리 소유로 확정된다(30초로 맞추면 경합 → 비결정적).
- **180초의 하한 근거:** "느리지만 정상"인 날(39 × 3초 = 117초)을 자르지 않아야 한다. 120초로 조이면 기사를 버리기 시작한다.
