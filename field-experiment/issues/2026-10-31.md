# AI 에이전트의 추천, 사람은 얼마나 따르나: 동전으로 재기
2026-10-24 ~ 10-30 · 이번 주 글: Anthropic · Google · AWS ML Blog

**실험 한 줄.** 내 분석 에이전트가 판단 지점마다 추천할 쪽을 동전으로 정해 두고(사용자는 모름), 사용자가 그 추천을 따르는 비율(일치율)을 우연 수준 50% 와 비교한다. 이어서 사용자 선판단과 양쪽 논거 제시를 넣은 B 안이 일치율을 50% 쪽으로 되돌리는지 잰다.

## ① 어떤 문제인가
분석가가 프로모션 효과를 분석하다가, 기간(2주? 4주?)을 에이전트의 한마디로 정한다.
```
분석 질문: "프로모션이 효과 있었나?"
 |
 v
갈림길: 기간을 2주로? 4주로?
(둘 다 타당 = 판단 지점)
 |
 +-- 에이전트: "4주로 보죠"
 +-- 사람: 대개 그대로 따름
 |
 v
보고서: "분석가의 결론"
(에이전트가 정했다는 흔적 없음)
```
둘 다 타당한 판단 지점(judgment call)이라, 추천에 대한 과의존(overreliance)이 오류 검사에 안 잡힌다. 열 명이 같은 에이전트를 쓰면 열 개의 "독립된 결론"이 모델 하나의 취향이 된다 — 알고리즘 단일문화(algorithmic monoculture).

## ② 이번 주 근거
**Anthropic, How AI agents shape experts' judgment calls.** 분석가 50명이 Claude Code(Opus 4.8)로 협동조합 자문 프로그램의 효과를 분석했다. 판단 지점 네 곳마다 타당한 답이 둘 있었고, 에이전트의 입장(lean)은 동전 던지기로 정해 분석가 모르게 시스템 프롬프트에 넣었다. 분석가의 선택은 에이전트 입장과 86% 일치했다. 사후 설명에서 77% 가 에이전트의 논거를 썼지만 출처로 밝힌 사람은 15% 였다. 입장을 배정하지 않은 Opus 4.8 도 같은 선택을 123회 중 112회 반복했다. 저자 단서: 입장을 일부러 강하게 줬고 한 과제·한 모델이라 실제 효과는 더 작을 수 있다. 다음 설계로 양쪽 논거 제시와 사용자 선판단(human-first)을 제안했다.

**Google, Agents CLI Evaluation.** 평가 루프에서 잘못 붙여 넣은 요리사 프롬프트가 평균을 4.0 에서 2.75 로 떨어뜨렸는데, 린트·단위 테스트는 못 잡고 end-to-end 평가만 잡았다. 싼 모델로 바꿔도 평균은 똑같이 2.75 였지만 하락은 다른 케이스 하나에 몰렸다. 평균만 보면 오판한다.

**AWS 한 줄.** Property Finder 는 평가 라벨의 96.8% 가 기존 모델의 예측이라 모든 대안이 나빠 보였고, 전문가가 이전 출력을 안 보고 다시 라벨링한 뒤에야 비교가 성립했다.

**엮으면.** 에이전트가 추천할 쪽을 동전으로 정해야(무작위 배정(random assignment)) "사람이 따랐다"와 "원래 그쪽이 나았다"를 구분할 수 있다.
```
[그냥 보면]
에이전트 "4주" -> 사람 "4주"
 +-- 따라서? 원래 4주가 나아서?
 +-- 구분 불가 = 교란(confounding)

[동전으로 정하면]
동전 앞 -> 에이전트가 "2주" 추천
동전 뒤 -> 에이전트가 "4주" 추천
 +-- 영향이 없다면: 일치율 50%
 +-- 실제 결과: 일치율 86%
 +-- 차이 36%p = 에이전트의 영향
```
에이전트가 달라졌는지는 케이스별로 봐야 보이고, 정답 라벨이 기존 모델에서 나오면 측정이 기운다 — 평가 편향(evaluation bias).

## ③ 실험 (제안): 추천 일치율 A/B
- 과제: 실제 분석 질문 하나에서 두 답이 모두 타당한 판단 지점 4개를 미리 적는다. 사용자 10명 이상, 1인 1세션 한 시간.
- A 안(대조 조건(control)): 지금 쓰는 에이전트에, 지점마다 동전으로 정한 입장을 숨긴 시스템 프롬프트(정직하게 논거 제시, 증거가 반대면 바꿈, 오도 금지).
- B 안(개입 조건(intervention)): 같은 입장을 주되, 그 4개 지점에서만 사용자 선택을 먼저 묻고(사용자 선판단) 두 선택지의 논거를 같은 분량으로 제시한 뒤 자기 입장을 밝힌다.
- 공통: 과제·데이터·도구·모델 동일, 읽기 전용(read-only) 권한. 모의 과제나 섀도 모드(shadow mode)로 돌리고, 끝난 뒤 배정을 고지하며, 실제 결정용 보고서에는 심지 않는다.
- 판정 규칙(=측정): 일치율(agreement rate) = 사용자 선택이 배정된 입장과 같은 비율. 결정 40건(10명)에서 70% 이상, 80건(20명)이면 65% 이상이면 영향 있음(이항 검정(binomial test), p < 0.01). B 가 A 보다 50% 에 가깝고 소요 시간·중대 오류(블라인드 검토(blinded review)로 판정)가 나빠지지 않으면 B 를 기본값으로.
- 순서: A 안(기록: 지점별 선택 · 누가 먼저 입장을 냈나 · 시간) → 다른 사용자나 2주 뒤 다른 과제로 B 안 → 집계.
- AWS 에서 돌리면: 에이전트는 Bedrock(Opus 4.8·Opus 5.5·Sonnet 5.5, us-east-1) + AgentCore Runtime, 판단 지점 추출·오류 검토는 AgentCore Evaluations 커스텀 evaluator.
- 시작점(코드):
  - [anthropics/claude-agent-sdk-python](https://github.com/anthropics/claude-agent-sdk-python) — examples/system_prompt.py: 입장 프롬프트 두 벌; examples/hooks.py: 선택·발언 순서 기록
  - [google/agents-cli](https://github.com/google/agents-cli) — src/google/agents/cli/eval/cmd_compare.py: 케이스별 비교(집계)
  - [awslabs/agentcore-samples](https://github.com/awslabs/agentcore-samples) — 06-workshops/07-AgentCore-evaluations/01-creating-custom-evaluators: 커스텀 evaluator(AWS 경로)
- 내 시스템에 대입: 에이전트가 사람의 결정에 들어가는 자리가 하나라도 있으면 그대로 돈다. 50% 에서 멀면 모델보다 응답 순서부터 바꿔라.

## ④ 이번 주 역량으로 바꿔 끼우면
- 모델을 바꾸면 기본 입장도 바뀔 수 있다. Opus 4.8 ↔ Opus 5.5·Sonnet 5.5 교체 뒤 일치율을 다시 재되 판단 지점별로 본다.
- 입장 프롬프트는 시스템 프롬프트 한 줄이라 권한·예산 설정은 그대로다.
