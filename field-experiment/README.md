## 1. 약속과 독자

- **독자:** 처음엔 사용자 본인. 두세 번 다듬은 뒤 동료에게 **별도 opt-in** 으로 개방한다. 데일리 수신자가 자동으로 받지 않는다.
- **약속:** 기사는 매주 토요일. 코드는 뒤따르며, 빌드 · 수락 테스트를 통과하면 링크를 붙인다. 코드가 늦어도 기사 발송은 깨지지 않는다.
- **목적(PRD):** 독자가 ① 비즈니스 가치를 검증하고 ② 아키텍처 · 구현 방법을 알고 ③ 자기 과제에 쓰게 한다. 여기서 "가치 검증"은 숫자를 보여 주는 것이 아니다. 랩 · 고객의 숫자는 조직 결과라 방향으로만 재현된다. 독자가 **자기 데이터로 잴 자(판정 규칙)** 를 함께 주는 것이 검증이다.

## 2. Verified Dispatch(데일리)와의 관계

- **입력은 데일리의 산출물을 읽기 전용으로 쓴다.** DynamoDB(us-east-1): `briefing-ledger`(run_date · card_key · decision · headline) · `briefing-card-cache`(card_json) · `briefing-source-store`(원문 · url · fetched_at). **코드는 데일리 것을 재사용한다**(`src/briefing/weekly/` + 이음매 4곳 — `delivery-plan.md` §4). 데일리 메일 · 데일리 동작은 바꾸지 않는다.
- **신뢰 표시가 다르다.** 데일리 인장은 "모든 주장이 원문 대조를 통과했다"는 뜻. 이 기사는 ② 근거의 사실만 그 기준을 쓴다 — **사실은 데일리 PUBLISH 카드의 동결 원문 전체에서 가져오고, 문장마다 Codex 가 같은 원문과 대조한다**(2026-11-04 결정 "2안": 데일리 claims 는 작성자의 읽기 보조, 대조 대상은 원문). ③ ④ 는 **제안**이다. 그래서 다른 브랜드다. 격리(QUARANTINE) 카드의 숫자는 인용하지 않는다.
- **같은 저장소, 다른 폴더.** 브리핑 저장소의 CLAUDE.md 규칙(착수 전 승인 · 런타임 격리 · AWS 접근 방식)이 그대로 적용된다.

## 5. 씨앗 선정(2026-10-25 확정)

**하드 게이트 3** — 모두 통과해야 씨앗이다.

1. **프론티어 랩 1차 글.** Anthropic(Claude Blog · News · Engineering) > Google(DeepMind · Developers · Cloud AI) > OpenAI. Applied AI / AI Agents 영역이고, 그 주 데일리에서 PUBLISH 된 카드.
2. 설계 · SDK 수준에서 **재현 가능한 메커니즘**이 있다.
3. ③ 에 **AWS 경로**(Bedrock · Claude Platform on AWS · 오픈소스)를 쓸 수 있다. 없으면 "확인 필요"로 낮춰 두되 제외하지 않는다.

- **소프트 순위:** 같은 주 프론티어 글 2편 이상이 수렴 → 월요일 실행 가능성 → AWS 경로 명확성 → 이번 주 프론티어 역량 끼우기.
- **보강층(씨앗 불가):** AWS 고객 사례 · 참조 아키텍처(③ "AWS 에서 돌리면" 과 ② 한 줄), **빅테크 1차 글**(Meta · Microsoft · IBM · NVIDIA 등, HF 블로그 기업 네임스페이스 포함 — 그 주 데일리 PUBLISH 카드만, ② 한 줄), 다른 영역 카드(Safety 등), 2차 보도(The Decoder).
- **모델 출시 글**은 ④ 로. 신모델은 선정 가중치가 아니다.
- **씨앗 없는 주:** Anthropic → Google → OpenAI 순으로 찾고, 없으면 "이번 주 아이디어 없음"을 보낸다. AWS 사례를 씨앗으로 빌리지 않는다.
- **단서(OpenAI):** OpenAI 1차 소스는 데일리 카탈로그에서 꺼져 있다(2026-07-17~, 본문이 Cloudflare 403 — 우회하지 않는다). 그래서 OpenAI 1차 카드는 없고, OpenAI 소식은 The Decoder 2차 보도(보강층)로만 들어온다. OpenAI 를 씨앗으로 쓰려면 전문을 싣는 합법 채널이 먼저다.

## 7. 시작점(코드) 저장소 규칙(2026-10-31)

- 저장소 링크는 **③ 의 "시작점(코드)" 목록에만.** ② ④ 출처에 없고, 데일리 메일 · `src/briefing` 에 넣지 않는다.
- **최대 3줄.** 각 줄 = `org/repo — 파일·디렉터리: 어느 안/단계`. 저장소 루트만 적지 않는다.
- **고르는 순서:** ① 씨앗 글이 직접 가리키는 저장소 → ② 그 랩의 공식 SDK · 쿡북 중 메커니즘을 구현한 파일이 있는 것 → ③ AWS 경로 저장소 1개 → ④ 서드파티는 그 저장소 자체가 메커니즘일 때만(예: 게이트웨이 실험의 LiteLLM).

- **당일 확인이 조건:** 리다이렉트 해소 → 최근 push → README/경로에 메커니즘 이름. 못 하면 링크 없이 보낸다. ## 8. 실험 장치(코드) 단계

- **기사와 분리.** 기사 발송은 코드에 의존하지 않는다. 코드는 빌드 · 수락 테스트를 통과하면 `demos/README.md` 와 다음 호에 링크로 붙는다.

- **원문 재수집:** 데일리 동결 원문에는 상한이 있다(8,000자 → 20,000자, 2026-10-28). 코드 단계는 후보 원문을 다시 가져온다.
